# ブースヒアリング（オフラインPWA）運用手順書

フォーラムday1のブースで、来場者のヒアリング内容をiPadに定型で記録するアプリです。データはiPad内（IndexedDB）にのみ保存し、外部には送信しません。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` | 画面とスタイル。CSPで外部への通信を禁止している（`connect-src 'self'`） |
| `app.js` | アプリ本体。先頭の `DEFAULT_CONFIG` が配信時の初期設定（仮の値） |
| `sw.js` | Service Worker。全ファイルをプリキャッシュし、オフラインで動かす。**更新時は `VERSION` を必ず変える** |
| `manifest.json` | ホーム画面追加用の定義 |
| `icons/` | アイコン（180 / 192 / 512 / maskable 512） |

ビルドや外部CDNは不要です。フォルダごと静的ホスティングに置けば動きます。

## 1. 動作確認手順

### 1-0. デスクトップで試す

```bash
cd booth-hearing
python3 -m http.server 8080
# → Chrome / Edge で http://localhost:8080/ を開く
```

- `localhost` は https でなくても Service Worker が動きます。
- DevToolsで「Application → Service Workers」に `sw.js` が activated と表示されていればOKです。「Network → Offline」にしてから再読み込みし、起動・入力・保存ができることを確認します。
- デスクトップのChromeは共有機能を使えない場合が多く、そのときCSVはダウンロードに切り替わります。

### 1-1. 配信（ホスティング）

- **https必須**です（iPadではhttpだとService Workerが動きません）。
- 静的ホスティングならどこでも構いません（Azure Static Web Apps、社内の静的Webサーバー、GitHub Pagesなど）。ページ配信だけに使い、データは受け取りません。
- サブディレクトリに置いても動きます（パスはすべて相対指定）。
- `sw.js` と `index.html` がブラウザに長時間キャッシュされないよう、可能なら `Cache-Control: no-cache` を設定します（更新を確実に届けるため）。

### 1-2. iPadでホーム画面に追加（端末ごとに1回）

1. **通信できる状態で**、SafariでURLを開きます。
2. 初回だけ端末IDを聞かれるので、端末ごとに重複しないIDを入れます（`iPad-01`、`iPad-02` …）。
   ※Safariのタブで設定した端末IDは、ホーム画面版には引き継がれません（手順5で設定し直します）。
3. 共有ボタン →「ホーム画面に追加」を押します（名前は「ヒアリング」）。
4. Safariのタブは閉じます。
5. ホーム画面のアイコンから起動し、端末IDをもう一度設定します。
6. 「設定」タブで次の3点を確認します。
   - 起動方法：**ホーム画面アプリ**
   - データ永続化：**✓ 有効**（「未許可」なら「永続化を再要求」を押す）
   - 更新：**最新（オフライン対応済み）**
7. アプリを一度閉じて再起動し、キャッシュが確実に入った状態にします。

### 1-3. オフライン起動の確認

1. コントロールセンターで**機内モード**にします（Wi-Fiもオフ）。
2. アプリをスワイプで完全に終了し、ホーム画面から起動します。
3. テストデータを2〜3件保存します（重複IDの警告、形式違いの警告、取り消し、一覧からの編集も試す）。
4. 次の「CSV書き出しの確認」まで済ませたら、テストデータは「設定 → 全データ削除」で消しておきます（連番はリセットされません。仕様です）。

### 1-4. CSV書き出しの確認

1. 画面上部の「最終バックアップ」をタップします（設定画面の「CSVを書き出す」でも同じ）。
2. 「差分のみ」または「全件」を選ぶと、共有シートが開きます。
   - **ファイルに保存**：「このiPad内」の任意のフォルダに保存します（機内モードでも可）。
   - **AirDrop**：回収用のMacやiPhoneに送ります（Bluetooth・Wi-Fiが必要）。
   - **メール**：通信できるときだけ使えます。社外への送信にならないよう、宛先は社内アドレスに限定します。
3. 共有シートを閉じる（キャンセル）と「書き出し済み」として記録されません。
4. 書き出すと上部の時刻が更新されます。書き出しから2時間以上たち、未書き出しの記録があると、オレンジ色で点滅して知らせます。

**当日の推奨運用**：1時間おきを目安に「差分のみ」を「ファイルに保存」し、撤収時に「全件」を書き出して回収します。

### 1-5. 本番前チェックリスト（iPad実機で確認すること）

- [ ] 縦向き・横向きで、ボタンが押しやすくレイアウトが崩れない
- [ ] テンキーで入力するとき、ソフトウェアキーボードが邪魔にならない（入力欄を直接タップするとキーボードが出る）
- [ ] 一言メモ欄でマイクボタンから音声入力できる（**音声入力は機内モードでも動くか**を端末の設定で確認する。オンデバイス認識が使えない言語設定だと通信が必要）
- [ ] 保存したあと自動で空の画面に戻り、担当者が前回の選択のまま残る
- [ ] ステータスバー（時計・電池）とボタンが重ならない
- [ ] アクセスガイド（設定 → アクセシビリティ → アクセスガイド）を開始しても、共有シートが操作できる
- [ ] 機内モードで「ファイルに保存」ができ、ファイルアプリで開ける
- [ ] 回収したCSVをExcelで開いて、文字化けしない

### 1-6. アプリの更新（Service Workerの更新手順）

1. ファイルを修正します（選択肢の初期値を変えるときは `app.js` の `DEFAULT_CONFIG`）。
2. **`sw.js` の `VERSION` を必ず上げます**（例：`1.0.0` → `1.0.1`）。上げないと、端末は古いキャッシュを使い続けます。`app.js` の `APP_VERSION` も合わせて上げます。
3. ホスティングにアップロードします。
4. 各iPadを通信できる状態にして、アプリを起動します。
5. 「設定 → 更新を確認」を押します。「新しいバージョンがあります」と表示されたら「更新して再読み込み」を押します。
6. 設定画面の「アプリ版／キャッシュ」が新しいバージョンになっていることを確認します。

- 更新しても保存済みの記録は消えません（IndexedDBはキャッシュと別の場所にあるため）。入力途中の内容も下書きとして残ります。
- 入力中に勝手に画面が切り替わらないよう、自動では更新しない設計にしています。**更新は会期前に済ませ、会期中は原則として更新しない**でください。

## 2. Excelでの結合手順

### 2-1. CSVの仕様

- UTF-8（BOM付き）、改行CRLF、全項目をダブルクオートで囲んでいます。
- 列：レコードID、端末ID、連番、保存時刻、フォーラムID、対応担当者、来場者との関係、関心領域、現在の課題、検討フェーズ、次アクション、温度感、メモ、**更新時刻**（一覧から編集した記録だけ入る。仕様に追加した列）
- 複数選択の項目は `;` 区切りです。保存時刻はタイムゾーン付きのISO形式です（例：`2026-10-15T14:32:05+09:00`）。
- メモが `= + - @` で始まる場合は、先頭に `'` を付けて書き出します（Excelで数式として実行されるのを防ぐため）。
- レコードID（`端末ID-連番`）は、端末IDが重複していなければ全端末を通して一意です。

### 2-2. 複数台のCSVを結合する（Power Query、推奨）

ダブルクリックで開くと、フォーラムIDの先頭の0が消えたり（`012345` → `12345`）、日時が変換されたりします。Power Queryで読み込むのが確実です。

1. 回収したCSVを、すべて1つのフォルダに入れます（差分ファイルと全件ファイルが混ざっていても構いません。手順5で重複を除きます）。
2. Excelで「データ → データの取得 → ファイルから → **フォルダーから**」を選び、手順1のフォルダを指定します。
3. 「結合 → **データの結合と変換**」を選びます。サンプルファイルの画面で、元のファイルの文字コードが「65001: Unicode (UTF-8)」、区切り記号が「コンマ」になっていることを確認します。
4. Power Queryエディターで次のとおり設定します。
   - `フォーラムID`、`レコードID`、`端末ID` の列を右クリック →「型の変更 → **テキスト**」（先頭の0を消さないため）
   - `連番` → 整数
   - `保存時刻`、`更新時刻` → テキストのまま（日時として使いたい場合は「日付/時刻/タイムゾーン」）
5. 重複を除きます（差分と全件を両方入れた場合や、編集した記録がある場合）。
   - `更新時刻` を**降順**、`保存時刻` を降順で並べ替えます。
   - `レコードID` 列を右クリック →「**重複の削除**」を実行します。これで記録ごとに最新版の1行だけが残ります。
   - ※Power Queryの重複削除は、並べ替え直後だと順序が保証されないことがあります。確実にするには、並べ替えのあとに「インデックス列の追加」を挟んでから重複を削除します。
6. 不要な `Source.Name` 列を削除し、「閉じて読み込む」で `ヒアリング` テーブルとして出力します。
7. あとからCSVが追加されたら、フォルダに入れて「データ → すべて更新」を押すだけです。

**Power Queryを使わない簡易手順**：各CSVを「データ → テキストまたはCSVから」で読み込み（フォーラムIDはテキスト型に変更）、1枚のシートに縦に貼り付けます。そのあと「データ → 重複の削除」をレコードID列だけで実行します（先に更新時刻の降順で並べ替えておく）。

### 2-3. 事務局の参加者リストとXLOOKUPで突合する

前提：事務局の参加者リストがテーブル `参加者`（列：`フォーラムID`、`社名`、`氏名` など）、結合したヒアリング結果がテーブル `ヒアリング` になっているものとします。**社名・氏名を付けた突合後のファイルは、社内の管理ルールに従って保管してください。**

`ヒアリング` テーブルに列を追加し、次の式を入れます。

```excel
社名 =XLOOKUP([@フォーラムID], 参加者[フォーラムID], 参加者[社名], "（該当なし）")
氏名 =XLOOKUP([@フォーラムID], 参加者[フォーラムID], 参加者[氏名], "（該当なし）")
```

型が合わずに一致しない場合（片方が数値、片方が文字列）は、両方を文字列にそろえます。

```excel
=XLOOKUP(TEXT([@フォーラムID],"000000"), TEXT(参加者[フォーラムID],"000000"), 参加者[社名], "（該当なし）")
```

複数の列をまとめて取得する場合（`参加者` の社名〜部署が隣り合っているとき）：

```excel
=XLOOKUP([@フォーラムID], 参加者[フォーラムID], 参加者[[社名]:[部署]], "（該当なし）")
```

※テーブル内ではスピル（複数セルへの展開）ができないため、この式はテーブルの外のセルで使います。

**使えるチェック・集計**

- 「（該当なし）」の行 → フォーラムIDの入力ミスの可能性があります（アプリで形式違いの警告を出したうえで保存した記録など）。
- 温度感Aで「商談希望」「デモ希望」の行 → 優先的にフォローする対象です。
- 関心領域・課題の件数 → Power Queryで該当列を選び、「列の分割 → 区切り記号 `;` → **行**に分割」してからピボットテーブルで集計します。

## 3. 既知の制約・注意点

### ストレージ（iPadOS / Safari）

| # | 内容 | 対策 |
|---|---|---|
| 1 | **Safariのタブとホーム画面アプリでは、保存場所が別です。** Safariで入力したデータは、ホーム画面版からは見えません。 | 必ずホーム画面のアイコンから起動します。タブで開くと警告が出ます。 |
| 2 | **ホーム画面のアイコンを削除すると、そのアプリのデータも消えます。** | 撤収時に全件CSVを回収するまで、アイコンを削除しないでください。 |
| 3 | 「設定 → Safari → 履歴とWebサイトデータを消去」でもデータが消えます。 | 会期中は操作禁止にします。 |
| 4 | 端末の空き容量が極端に少ないと、OSがWebデータを削除することがあります。`persist()` が許可されていれば対象外になりますが、iPadOSの判定基準は公開されていません。 | 空き容量を数GB確保し、こまめにCSVを書き出します（2時間でアラートが出ます）。 |
| 5 | Safariの「使われていないサイトのデータを7日で消す」仕組みは、ホーム画面アプリには適用されない仕様です。ただし、Safariのタブで使った場合は対象になります。 | #1と同じです。 |
| 6 | アプリの設定・下書き・「前回の担当者」もすべて端末内にあります。端末間で自動同期はしません。 | 選択肢は `DEFAULT_CONFIG` を書き換えて配信すると、全台に一括で反映されます。 |
| 7 | 下書き（入力途中の内容）は `localStorage` に保存しています。アプリが強制終了されても、再起動すると入力途中の内容が戻ります。 | ─ |

### キャッシュ・更新

| # | 内容 | 対策 |
|---|---|---|
| 8 | `sw.js` の `VERSION` を変えないと、端末は古い版を使い続けます。 | 更新手順（1-6）を守ります。 |
| 9 | 更新は、通信できる状態でアプリを開いたときだけ取得されます。機内モードのままでは更新されません。 | 会期前日までに全台で更新し、版を確認します。 |
| 10 | 新しい版が取得されても、「更新して再読み込み」を押すまで切り替わりません（入力中の事故を防ぐため）。 | 設定タブに「!」が付いたら、手の空いたときに更新します。 |
| 11 | ホスティングのURL（ドメインやパス）が変わると別のアプリとして扱われ、データも別になります。 | 会期前にURLを確定し、変えないでください。 |

### 書き出し・運用

| # | 内容 | 対策 |
|---|---|---|
| 12 | 「差分」は、前回の書き出し以降に**新規作成・編集**された記録です。**削除した記録は差分に出ません**（書き出したあとに削除した記録は、回収済みのCSVに残ります）。 | 最終回収は「全件」で行い、全件ファイルを正本にします。 |
| 13 | 共有シートで「ファイルに保存」を選んだあと、その画面でキャンセルしても、アプリ側では書き出し済みになる場合があります（iPadOSの挙動）。 | 心配なときは「全件」で再度書き出します。 |
| 14 | 取り消し・編集・削除した記録は元に戻せません（ゴミ箱はありません）。削除できるのは「直前の1件を取り消す」「一覧から削除」「全データ削除」の3か所だけで、どれも確認ダイアログがあります。 | ─ |
| 15 | 連番は取り消しや全データ削除をしても戻りません（欠番が出ます）。レコードIDの重複を防ぐための仕様です。 | ─ |
| 16 | 2台に同じ端末IDを設定すると、レコードIDが重複します。アプリでは検出できません。 | 端末の背面に端末IDのシールを貼ります。 |
| 17 | 「アンケートを開く」は外部ページに移動します（通信が必要）。アクセスガイド中は、Safariへの切り替えが制限される場合があります。 | 事務局アンケートは別の端末や紙のQRで案内するのが確実です。ボタンはURLを設定したときだけ表示されます。 |
| 18 | ホーム画面アプリでは、iPadOSの仕様上 `display: fullscreen` は使えず、ステータスバー（時計など）は表示されたままです（`standalone` 表示。ブラウザのUIは出ません）。 | ─ |
| 19 | 一言メモに社名などが入力されても、アプリは検出できません（常に注意書きを表示しているだけです）。 | 回収後、メモ列を目視で確認します。 |
| 20 | 保存時刻は端末の時計を使います。 | 会期前に「日付と時刻 → 自動設定」がオンになっていることを確認します。 |

## 設定項目（仮の値）

| 項目 | 変更場所 | 仮の値 |
|---|---|---|
| 端末ID | 初回起動時／設定画面 | iPad-01 |
| 担当者名簿 | 設定画面／`DEFAULT_CONFIG.staff` | 担当A〜担当E |
| 関心領域 | 設定画面／`DEFAULT_CONFIG.interests` | テーマ1〜テーマ5 |
| 現在の課題 | 設定画面／`DEFAULT_CONFIG.issues` | 課題1〜課題6（＋その他は自動） |
| フォーラムIDの形式 | 設定画面／`DEFAULT_CONFIG.forumId` | 数字6桁 |
| 事務局アンケートURL | 設定画面／`DEFAULT_CONFIG.surveyUrl` | 未設定（ボタン非表示） |
| 関係・フェーズ・次アクション・温度感の説明 | `app.js` の `FIXED` | 仕様どおり（温度感の説明文は仮） |

**おすすめ**：選択肢が確定したら、設定画面で1台ずつ入力するのではなく、`DEFAULT_CONFIG` を書き換えて配信（`VERSION` を上げる）すると、全台の入力内容がそろいます。
